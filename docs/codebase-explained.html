ITransferable.h

C++ חדש
החוזה האחיד לכל דבר שניתן לשלוח — קובץ, טקסט, או כל סוג עתידי. כל מי שרוצה לשלוח משהו חייב לממש ממשק זה. זהו לב ה-Open-Closed Principle בפרויקט: להוסיף סוג חדש = class חדש, לא שינוי בקוד קיים.

🔑 Open-Closed Principle

קוד פתוח להרחבה, סגור לשינוי. ITransport::send() מקבל ITransferable& — הוא לא יודע אם זה קובץ או טקסט. כשנוסיף ContactTransferable בעתיד — ITransport לא ישתנה בכלל.

#pragma once
אומר לקומפיילר: "טען קובץ זה פעם אחת בלבד". מונע הגדרה כפולה.
#include "IProtocol.h"
צריך את MessageHeader שמוגדר ב-IProtocol.h — כדי שנדע מה makeHeader מחזיר.
#include <vector> #include <cstdint> #include <string_view>
ספריות סטנדרטיות: vector לרשימת bytes, uint8_t לסוג byte, string_view לטקסט read-only.
ה-Interface עצמו
namespace BetterSend {
namespace = "מרחב שמות". כל קוד הפרויקט עטוף ב-BetterSend כדי למנוע התנגשות שמות עם ספריות אחרות.
class ITransferable { public:
הגדרת interface. ב-C++ אין מילת interface — ממשים עם class שכל הפונקציות שלו pure virtual. ה-I בשם = מוסכמה: "I" פירושו Interface.
virtual ~ITransferable() = default;
virtual destructor — חובה בכל interface.
בלי זה, אם נמחק ITransferable* שמצביע ל-FileTransferable, ה-destructor של FileTransferable לא יקרא ← דליפת זיכרון.
= default = "תן לקומפיילר לייצר מימוש ריק".
[[nodiscard]] virtual MessageHeader makeHeader( std::string_view senderName) const = 0;
[[nodiscard]]: warning אם קוראים ולא שומרים תוצאה.
virtual ... = 0: pure virtual — כל subclass חייב לממש.
string_view: טקסט read-only בלי copy — יעיל.
const: הפונקציה לא משנה את האובייקט.
[[nodiscard]] virtual std::vector<uint8_t> payload() const = 0;
מחזיר את ה-bytes לשלוח אחרי ה-header.
vector<uint8_t> = רשימה של bytes (uint8_t = מספר 0-255, גודל byte אחד).
לקובץ: תוכן הקובץ. לטקסט: UTF-8 encoding של הטקסט.
};
סגירת ה-class. נקודה-פסיק אחרי } היא חובה ב-C++ (שלא כמו ב-Java/JS).
} // namespace BetterSend
סגירת ה-namespace. ה-comment מזכיר לנו מה נסגר.

IProtocol.h

C++
מגדיר שני דברים: (1) MessageHeader — המבנה של header הודעה, (2) IProtocol — ממשק לקידוד ופענוח headers. הפרוטוקול רק אחראי על ה-header, לא על ה-payload.

🔌 Wire Format — פורמט ההודעה על הרשת

כל הודעה נשלחת כך:

[ 4 bytes: אורך ה-JSON ][ N bytes: JSON header ][ M bytes: payload ]

ה-4 bytes הראשונים הם big-endian uint32 — אומרים כמה bytes הוא ה-JSON. אז קוראים את ה-JSON (שמכיל סוג, שם, גודל, שם שולח), ואז את ה-payload עצמו.

MessageHeader — מבנה הנתונים
struct MessageHeader { enum class Type : uint8_t { File, Clipboard };
struct: כמו class אבל הכל public כברירת מחדל. משמש ל-data objects.
enum class: רשימת ערכים עם שם (type-safe). : uint8_t = יאוחסן ב-byte אחד.
שני סוגים: קובץ (File) וטקסט/לוח (Clipboard).
Type type{};
{} = אתחול ל-0 (ל-File). בלי זה — ערך לא מוגדר (undefined behavior).
std::string name; // Filename
שם הקובץ. ריק עבור Clipboard (אין שם קובץ).
std::size_t size{}; // Payload size in bytes
size_t = מספר חיובי בגודל המתאים לפלטפורמה (64-bit במחשב 64-bit). לא משתמשים ב-int כי גודל קובץ יכול לעלות על 2GB.
std::string senderName;
שם המכשיר השולח (מה שהמשתמש הגדיר, למשל "iPhone של יונתן").
IProtocol — ממשק הקידוד
[[nodiscard]] virtual std::vector<uint8_t> encodeHeader( const MessageHeader& header) = 0;
מקבל MessageHeader → מחזיר bytes לשלוח על הרשת.
const ... & = reference (לא copy) + לא ישתנה. יעיל לאובייקטים גדולים.
[[nodiscard]] virtual MessageHeader decodeHeader( std::span<const uint8_t> data) = 0;
span: "חלון" לתוך array קיים, בלי copy. בטוח יותר מ-raw pointer כי שומר גם את האורך.
זורק runtime_error אם ה-data פגום.

ITransport.h

C++
ממשק ה-Strategy לשכבת התקשורת. מגדיר מה Transport יכול לעשות, לא איך. המימוש הנוכחי: TcpTransport. בבדיקות: MockTransport.
Transfer — תוצאת קבלה
struct Transfer { enum class Type : uint8_t { File, Clipboard }; Type type; std::string senderName; std::string name; std::size_t sizeBytes{}; std::string data; };
מה שמגיע ל-callback כשמתקבלת העברה:
• type: קובץ או clipboard
• senderName: שם המכשיר ששלח
• name: שם קובץ (ריק ל-clipboard)
• data: לקובץ = נתיב שמירה, לטקסט = התוכן עצמו
ITransport — ממשק
virtual void startServer(int port, std::function<void(Transfer)> onReceive) = 0;
std::function<void(Transfer)>: סוג של callback — כל פונקציה שמקבלת Transfer ומחזירה void.
יכול להיות lambda, פונקציה רגילה, או method עם bind.
ה-callback יקרא מ-thread רקע — חשוב לסנכרון!
virtual void send(const std::string& ip, int port, const ITransferable& item) = 0;
OCP בפעולה: Transport לא יודע אם item הוא קובץ, טקסט, או כל דבר אחר. הוא פשוט קורא item.makeHeader() + item.payload(). להוסיף סוג חדש = לא לשנות שורה זו.
virtual void stop() = 0;
עוצר server ומחכה שכל ה-threads יסיימו (blocking). חובה לקרוא לפני השמדת האובייקט.

IDiscovery.h

C++
ממשק לגילוי מכשירים ברשת המקומית. משתמש ב-mDNS (Multicast DNS) — אותו פרוטוקול שמאחורי Bonjour של Apple ו-AirDrop.

🌐 mDNS — איך זה עובד

כל מכשיר "מכריז" על עצמו ברשת עם שם שירות _bettersend._tcp.local. מכשירים אחרים מקשיבים לכריזות אלה ומגלים אחד את השני. לא צריך שרת מרכזי — peer-to-peer לחלוטין.

virtual void startAdvertising( const std::string& deviceName, int port) = 0;
מכריז "אני קיים" לרשת. שולח UDP multicast לכתובת 224.0.0.251:5353 עם שם המכשיר והפורט שעליו אנחנו מאזינים.
virtual void startDiscovery( std::function<void(Device)> onFound) = 0;
מחפש מכשירים שגם הם מריצים BetterSend. לכל מכשיר שנמצא — קורא ל-onFound עם ה-Device שלו.
virtual void stop() = 0;
עוצר גם advertising וגם discovery. מחכה ש-threads ייצאו (blocking).

FileTransferable.h

C++ חדש
מימוש של ITransferable לקבצים. יודע לקחת path לקובץ ולספק header + bytes.
#include <filesystem> #include <fstream>
filesystem: C++17 — עבודה עם paths, גדלי קבצים. fstream: קריאת/כתיבת קבצים.
explicit FileTransferable(std::filesystem::path path) : path_{std::move(path)} {}
explicit: מונע המרה אוטומטית לא מכוונת (למשל string ← FileTransferable בטעות).
std::move: מעביר בעלות על ה-path בלי copy. יעיל.
MessageHeader makeHeader(std::string_view senderName) const override { return MessageHeader{ .type = MessageHeader::Type::File, .name = path_.filename().string(), .size = std::filesystem::file_size(path_), .senderName = std::string(senderName), }; }
override: אומר לקומפיילר "אני מוודא שזו באמת דריסה של פונקציה virtual מה-base". אם שגינו בשם — error.
.filename(): מחלץ רק שם הקובץ מה-path המלא (למשל /photos/cat.jpg → cat.jpg).
Designated initializers (.type=, .name=) — C++20.
std::vector<uint8_t> payload() const override { std::ifstream f(path_, std::ios::binary); if (!f) throw std::runtime_error(...); return std::vector<uint8_t>( std::istreambuf_iterator<char>(f), std::istreambuf_iterator<char>() ); }
קורא את כל תוכן הקובץ ל-vector של bytes.
istreambuf_iterator: iterator שקורא byte-by-byte מ-stream — הדרך הנפוצה לקרוא קובץ לvector.
std::ios::binary: חובה — בלי זה Windows ממיר \r\n ל-\n ופוגם בקבצים.
private: std::filesystem::path path_;
המשתנה היחיד: ה-path לקובץ. _ בסוף שם = מוסכמה לmember variables פרטיים.

TextTransferable.h

C++ חדש
מימוש של ITransferable לטקסט (clipboard). פשוט יותר מ-FileTransferable.
MessageHeader makeHeader(...) const override { return MessageHeader{ .type = MessageHeader::Type::Clipboard, .name = {}, .size = text_.size(), ... }; }
name = {}: string ריקה — לטקסט אין שם קובץ.
text_.size(): גודל ב-bytes של הטקסט (UTF-8 יכול להיות יותר bytes ממספר תווים).
std::vector<uint8_t> payload() const override { return std::vector<uint8_t>( text_.begin(), text_.end()); }
הופך string ל-vector של bytes. string הוא כבר UTF-8 ב-C++, אז פשוט מעתיקים את ה-bytes שלו.

BonjourDiscovery.cpp

C++ Apple בלבד
מימוש של IDiscovery ל-macOS/iOS באמצעות Bonjour (dns_sd.h). עובד דרך mDNSResponder של המערכת — sandbox-compatible, לא דורש הרשאות מיוחדות.
MdnsDiscovery.cpp (raw UDP port 5353) משמש Android, Linux, Windows.
תמיכה ב-Windows: GetAdaptersAddresses במקום getifaddrs (POSIX-only). headers בתוך #ifdef _WIN32.
שני המימושים מרשמים _bettersend._tcp.local. — מכשיר Apple ומכשיר Windows יזהו אחד את השני באותה רשת.

📡 Bonjour + AWDL — גילוי ללא WiFi משותף

ב-macOS, mDNSResponder מנהל את כל תעבורת ה-mDNS. ניסיון לקשור raw UDP לport 5353 נחסם על ידי ה-sandbox.
Bonjour API: מדבר ישירות עם mDNSResponder דרך Unix socket — sandbox-compatible.
AWDL (Apple Wireless Direct Link): רשת WiFi peer-to-peer ישירה בין מכשירים — ללא router. זו אותה טכנולוגיה שמשמשת AirDrop.
kDNSServiceFlagsIncludeAWDL: מרחיב את הגילוי מ"אותה רשת" ל"קרוב פיזית".
שרשרת הקריאות: Browse מוצא שם שירות → Resolve מוצא hostname:port → GetAddrInfo מוצא IP.

Shared Connection
DNSServiceCreateConnection(&mainRef_); static constexpr DNSServiceFlags kP2PFlags = kDNSServiceFlagsShareConnection | kDNSServiceFlagsIncludeAWDL | // peer-to-peer WiFi kDNSServiceFlagsIncludeP2P; // other P2P interfaces
kDNSServiceFlagsShareConnection: כל ה-sub-operations חולקים fd אחד.
kDNSServiceFlagsIncludeAWDL: מפעיל AWDL — מצא מכשירים קרובים ללא WiFi משותף, כמו AirDrop.
kDNSServiceFlagsIncludeP2P: ממשקים P2P נוספים.
Browse → Resolve → GetAddrInfo chain
static void browseCb(..., const char* serviceName, ...) { // serviceName = device display name (e.g. "iPhone-Yoni") auto* rc = new ResolveCtx{st, serviceName}; DNSServiceRef resolveRef = st->mainRef; DNSServiceResolve(&resolveRef, kDNSServiceFlagsShareConnection, ifIdx, serviceName, regtype, domain, resolveCb, rc); }
מקבל שם שירות → מתחיל Resolve לקבלת hostname:port.
new ResolveCtx: מעביר את שם המכשיר הלאה בשרשרת — יימחק ב-resolveCb.
kDNSServiceFlagsAdd: מסנן רק מכשירים חדשים (לא "remove" events).
static void resolveCb(..., const char* hosttarget, uint16_t port, ...) { auto* ac = new AddrCtx{rc->state, rc->serviceName, ntohs(port)}; delete rc; DNSServiceGetAddrInfo(&addrRef, kDNSServiceFlagsShareConnection | kDNSServiceFlagsTimeout, ifIdx, kDNSServiceProtocol_IPv4, hosttarget, addrInfoCb, ac); }
מקבל hostname:port → מבקש IP.
ntohs(port): ממיר מ-network byte order (big-endian) ל-host byte order.
kDNSServiceFlagsTimeout: אם לא נמצא IP בזמן — callback עם שגיאה (לא תקוע לנצח).
static void addrInfoCb(..., const sockaddr* addr, ...) { inet_ntop(AF_INET, &sin->sin_addr, ipbuf, ...); ctx->state->onFound(Device{ctx->serviceName, ip, ctx->port}); DNSServiceRefDeallocate(sdRef); delete ctx; }
סוף השרשרת: יש שם + IP + port → בונים Device וקוראים ל-callback.
inet_ntop: ממיר כתובת IP בינארית ל-string קריא.
seen set + mutex: מונע duplicate callbacks לאותו IP.
Event Loop
while (running_ && mainRef_) { int fd = DNSServiceRefSockFD(mainRef_); fd_set fds; FD_ZERO(&fds); FD_SET(fd, &fds); struct timeval tv{0, 100000}; if (select(fd+1, &fds, nullptr, nullptr, &tv) > 0) DNSServiceProcessResult(mainRef_); }
DNSServiceRefSockFD: מחזיר Unix socket ל-mDNSResponder.
select + DNSServiceProcessResult: הגישה הנכונה ל-Bonjour async — חוסמים 100ms, מעבדים כשיש נתונים.
כל ה-callbacks (browse, resolve, addrInfo) מגיעים דרך loop זה.
Factory
std::unique_ptr<IDiscovery> makeDiscovery() { return std::make_unique<BonjourDiscovery>(); }
אותה חתימה כמו ב-MdnsDiscovery.cpp — ה-CMakeLists.txt מחליט איזה קובץ לקמפל.
Apple → BonjourDiscovery. שאר הפלטפורמות → MdnsDiscovery.

Constants.h

C++
כל ה"מספרים הקסומים" של הפרויקט. כלל: לעולם לא לכתוב 9000 ישירות בקוד — תמיד kDefaultPort.
inline constexpr int kDefaultPort = 9000;
constexpr: הערך ידוע בזמן קומפילציה — מהיר כמו literal, אבל עם שם.
inline: מאפשר הגדרה בheader בלי לגרום ל"הגדרה כפולה" כשה-header נטען ממספר קבצים.
inline constexpr char kServiceType[] = "_bettersend._tcp.local.";
שם שירות ה-mDNS. כל מכשיר שמריץ BetterSend מכריז ומחפש שם זה בדיוק.
inline constexpr uint32_t kHeaderLengthBytes = 4;
4 bytes = uint32 big-endian שאומר כמה bytes הוא ה-JSON header.
inline constexpr uint32_t kReceiveBufferSize = 65536;
64KB — גודל buffer לקריאה ברשת. קורא עד 64KB בכל "סיבוב" של recv.
inline constexpr char kBleServiceUuid[] = "5BE77ECD-A1B2-4F1A-8C5D-7F8E9D2C4A6B"; inline constexpr uint16_t kBleCompanyId = 0xFFFF; inline constexpr uint8_t kBleMagicBytes[] = {0xBE, 0x77, 0xEC, 0xD0}; inline constexpr int kBleMaxNameLen = 20;
kBleServiceUuid: GATT service UUID לשלב ה-handshake (read SSID+PSK אחרי שהצד השני נמצא). לא נכנס לתוך ה-advertise כי 128-bit לבד תופס 18 בייטים — לא משאיר מקום לשם בתוך 31 הבייטים הלגאסי.
kBleCompanyId 0xFFFF: Bluetooth SIG שמור ל-development. כל BetterSend peer מציין שהוא BetterSend ע"י advertising של ManufacturerData עם ה-company ID הזה.
kBleMagicBytes: 4 בייטים אחרי ה-company ID — מסנן false-positives של אפליקציות אחרות שגם משתמשות ב-0xFFFF. ה-watcher מסנן ב-hardware על company + magic ביחד.
kBleMaxNameLen 20: גודל מקסימלי לשם מכשיר בתוך ה-advertise (3 AD Flags + 8 ManufacturerData overhead + magic = 15 כבר תפוסים, 31-15 = 16 לשם; שמרנו 20 לבטיחות עם חיתוך).

BleDiscovery.h + BleDiscovery_Windows.cpp

C++ Phase 1
Discovery של עמיתי BetterSend דרך Bluetooth Low Energy — ללא רשת משותפת, כמו שלב ה-discovery של AirDrop. ה-BleDiscovery.h מכריז על factory יחיד (makeBleDiscovery()); כל פלטפורמה מספקת קובץ .cpp/.mm משלה מאחורי הממשק. BleDiscovery_Windows.cpp מממש את צד ה-Windows עם C++/WinRT (BluetoothLEAdvertisementPublisher + BluetoothLEAdvertisementWatcher).
winrt_btle::BluetoothLEManufacturerData mfg; mfg.CompanyId(kBleCompanyId); mfg.Data(makeBetterSendPayload(deviceName)); adv.ManufacturerData().Append(mfg); publisher_.Start();
למה ManufacturerData ולא LocalName + ServiceUuid? הניסיון הראשון היה לשים את ה-Service UUID במכריז ולשם את ה-LocalName — נתן HRESULT 0x80070057 "The parameter is incorrect". הסיבה: AD Flags 3B + Service UUID 128-bit 18B + LocalName 10B = 33B, יותר מ-31 הבייטים של legacy advertisement. ב-ManufacturerData הסטטיק הוא 8B + 4B magic = 12B, ונשארים 19B לשם.
watcher_.AdvertisementFilter().Advertisement() .ManufacturerData().Append(filterMfg);
Hardware-level filter: ה-watcher מקבל callback רק על packets שעוברים את הסינון של ה-Bluetooth controller. מסנן אצלנו על company ID + magic prefix — אוזניות BLE, beacons, ושאר רעש שאינו BetterSend נחסם לפני שמגיע ל-app. חיסכון משמעותי ב-callbacks ובCPU.
std::lock_guard lock(seenMu_); if (!seen_.insert(addr).second) return;
Dedupe לפי BluetoothAddress. BLE advertising מתחדש כל ~100ms, ובלי dedupe ה-UI היה מקבל את אותו עמית עשרות פעמים בשנייה.
onFound_(Device{name, std::string("ble:") + addrStr, kDefaultPort});
ה-ip נושא "ble:<addr>" זמנית — סמן ש-discovery זוהה אבל transport עוד לא קיים. בשלב הבא (IConnectionBroker), Windows מעלה Mobile Hotspot, Mac מתחבר אליו, וה-ip יוחלף לכתובת IPv4 אמיתית.
// CMakeLists.txt target_link_libraries(bettersend_core PRIVATE ws2_32 mswsock iphlpapi runtimeobject ole32 oleaut32)
MinGW לא נושא את ה-cppwinrt headers (הם ב-Windows SDK תחת Program Files (x86)/Windows Kits/10/...). ה-CMake מאתר את הגרסה הכי חדשה ב-build time. ה-link דורש runtimeobject (WinRT activation), ole32 (COM), oleaut32 (BSTR / IErrorInfo). בלעדיהם — undefined references ב-link time.

bettersend_api.cpp

C++
ה-Facade של הפרויקט. חושף C API פשוט לצד Flutter. כל הקוד עטוף ב-try/catch כי exceptions לא יכולים לעבור את גבול ה-FFI.

🚧 למה extern "C"?

C++ מבצע "name mangling" — משנה שמות פונקציות (send הופך ל-_ZN10BetterSend4sendEv). extern "C" מבטל זאת — Flutter מצפא לשם bettersend_create בדיוק, לא גרסה mangled.

unique_ptr: smart pointer — מחיק את האובייקט אוטומטית כשה-context נהרס. אין צורך ב-manual delete.
מחזיקים את ה-interfaces (לא את המימושים) — Strategy Pattern בפעולה.

void*: pointer לא מוקלד — Flutter מחזיק כ"handle" אטום.
makeDiscovery(): Factory — יוצר MdnsDiscovery בלי לחשוף את המחלקה.
OCP: אם נרצה BLE discovery — רק שורת ה-factory משתנה.

🔗 איך FFI עובד

לכל פונקציה C צריך שני typedefs:
1. Native — חתימת C (עם Pointer, Int32, Void)
2. Dart — חתימת Dart (עם Pointer, int, void)
ואז lookupFunction שטוען את הפונקציה מה-dylib.
אין mock mode — real network behavior בלבד.

DynamicLibrary _loadLibrary() { if (Platform.isAndroid) return DynamicLibrary.open('libbettersend_core.so'); if (Platform.isIOS) return DynamicLibrary.process(); if (Platform.isMacOS) return DynamicLibrary.open('libbettersend_core.dylib'); if (Platform.isWindows) return DynamicLibrary.open('bettersend_core.dll'); throw UnsupportedError('Platform not supported'); } final DynamicLibrary _lib = _loadLibrary();
כל פלטפורמה טוענת שם קובץ אחר: .dylib (macOS), .dll (Windows), .so (Android), process() (iOS — הספרייה מוטמעת בbundle).
DynamicLibrary non-nullable — חובה שהספרייה תהיה built.
throw UnsupportedError: פלטפורמה לא נתמכת → crash מיידי עם הודעה ברורה.
typedef _NativeEcho = Pointer<Utf8> Function(Pointer<Utf8>); typedef _DartEcho = Pointer<Utf8> Function(Pointer<Utf8>); typedef NativeDeviceFoundCb = Void Function( Pointer<Utf8>, Pointer<Utf8>, Int32);
שני typedefs לכל פונקציה — חובה של Dart FFI.
NativeDeviceFoundCb: typedef לcallback — C יקרא לזה כשמוצא מכשיר.
Int32 בNative ↔ int בDart — המרה אוטומטית.
final _echo = _lib.lookupFunction<_NativeEcho, _DartEcho>('bettersend_echo'); final _create = _lib.lookupFunction<_NativeCreate, _DartCreate>('bettersend_create'); final _startDiscovery = _lib.lookupFunction<...>('bettersend_start_discovery');
ללא ? — non-nullable. אם הסמל לא קיים ב-dylib → ArgumentError עם שם הסמל.
כל הlookups רצים בזמן טעינה — בעיות נתפסות מיידית, לא רק כשהפונקציה נקראת.
void startDiscovery({required void Function(DiscoveredDevice) onFound}) { _discoveryCb = NativeCallable<NativeDeviceFoundCb>.listener( (Pointer<Utf8> namePtr, Pointer<Utf8> ipPtr, int port) { final name = namePtr.cast<Utf8>().toDartString(); final ip = ipPtr.cast<Utf8>().toDartString(); _freeCstr(namePtr.cast<Utf8>()); // release C-allocated buffer _freeCstr(ipPtr.cast<Utf8>()); onFound(DiscoveredDevice(name: name, ip: ip, port: port)); }); _startDiscovery(_handle, _discoveryCb!.nativeFunction); }
NativeCallable.listener: מעביר קריאות מ-C thread → Dart isolate async.
הערה קריטית: ב-listener mode הטיפוסים הגנריים של ה-Pointer לא שורדים את ה-isolate hop — ב-runtime הם מגיעים כ-Pointer<Never>. חובה annotation מפורש על פרמטרי ה-closure + .cast<Utf8>() ב-runtime כדי ש-toDartString ימצא את ה-extension.
Lifetime: C++ heap-alloc את ה-strings; אחרי toDartString חובה לקרוא ל-_freeCstr אחרת זה memory leak.
_discoveryCb חייב להישמר (member var) — אם יינפה, ה-C pointer יהפוך ללא תקף.
void dispose() { _discoveryCb?.close(); // releases native function pointer _destroy(_handle); // frees BetterSendContext on C++ heap }
close(): מנקה את ה-native function pointer — חובה למנוע memory leak.
_destroy(_handle): קורא ל-delete ctx ב-C++. בלי זה — memory leak של כל ה-discovery + threads.
